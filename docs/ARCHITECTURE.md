# 架构说明

## 核心原则

手机型号、材质支持、库存状态及售后风险属于确定性业务数据，不能交给大模型推断。

## 客服决策链

1. 检查会话是否已由人工接管
2. 匹配售后高风险、固定回复和忽略规则
3. 精确查询手机型号及不同材质支持状态
4. 命中高置信度已审核知识时直接回复
5. 将已审核知识与多轮历史交给 AI 组织自然回复
6. 未覆盖、AI异常或未知型号时转人工

## 核心模块

- `normalization.py`：品牌、材质、型号标准化
- `importer.py`：型号 XLSX/CSV 导入
- `service.py`：型号精确查询、相似型号、未知型号记录
- `rules.py`：售后高风险、固定回复、忽略规则
- `knowledge.py`：已审核客服知识的导入和检索
- `ai.py`：OpenAI 兼容模型接口与安全提示词
- `conversations.py`：多轮消息历史及人工接管状态
- `handoff.py`：转人工请求持久化
- `orchestrator.py`：统一决策顺序
- `channels.py`：渠道发送回复和转人工动作接口
- `cli.py`：导入、配置、测试回复和待转人工查询

## 平台适配边界

拼多多适配器只负责登录、接收消息、发送回复和执行转人工；业务判断全部由 `CustomerServiceOrchestrator` 完成，避免平台代码中出现分散规则。
